1 Пайвастшавӣ

GitHub Personal Access Token-ро ворид кунед. Барои амалиётҳои repo ҳуқуқи мувофиқ лозим аст.

Token-ро ба касе нафиристед. Барои истифодаи муваққатӣ checkbox-ро хомӯш гузоред.

Сохтани token ↗

2 Логи автоматии repository

Пас аз интихоби як repository, RepoPilot охирин GitHub Actions run-ҳоро мехонад, job/step-ҳои нокомро меёбад ва сабаби эҳтимолиро таҳлил мекунад.

Аввал як repository интихоб кунед.
Барои хондани run-ҳо token бояд Actions: read дошта бошад (fine-grained token). Агар GitHub зеркашии log-архивро аз браузер манъ кунад, номи run, job ва қадамҳои ноком нишон дода мешаванд; тугмаи кушодани Actions низ дастрас аст.

3 Таҳлили лог

Логро худкор аз Actions гиред ё матни логро дастӣ гузоред. Таҳлил дар браузер иҷро мешавад.

5 Сохтани repository

Repository-и навро бевосита дар аккаунти GitHub созед. Номи такрорӣ қабул намешавад.

Барои сохтани repository token бояд иҷозати мувофиқи Administration дошта бошад. Ин амал ягон repository-и мавҷударо нест намекунад.

Commit-ҳо дар ин ҷо нишон дода мешаванд.
